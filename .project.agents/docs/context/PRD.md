> 本文回答"做什么 / 给谁 / 为什么"，不回答"怎么实现"（那是 `ARCHITECTURE.md`）。

## 1. 产品愿景
为 AI 开发者与用户构建一个去中心化的、意图驱动的技能（Skill）自治网络。用户只需用自然语言表达需求，系统自动从去中心化市场匹配、编排并本地运行多个原子 Skill，所有价值流转（使用计次、创作者收益）通过区块链不可逆结算——零中心化运营，零服务器成本。

## 2. 目标用户与典型场景

### 用户画像
| 角色 | 行为 | 核心诉求 |
|------|------|----------|
| **Skill 创作者** | 编写/发布 Skill 到市场 | 获得算力积分/代币回报，作品被公平评分 |
| **Skill 使用者** | 通过万能入口执行需求 | 低成本获取高质量 AI 能力，不需自己写 Skill |
| **AI Agent 开发者** | 构建集成 AIMS 的应用 | 协议透明，接入简单，没有平台锁定 |

### 典型场景
1. **开发者 Alice** 编写了一个「代码安全审计 Skill」发布到 AIMS 市场，标注定价 0.5 积分/次。
2. **用户 Bob** 对万能入口说"帮我审计这个合约有没有重入漏洞"，万能入口自动拆解需求 → 在市场检索到 Alice 的 Skill → 在 Bob 本地执行 → 链上记录 Alice +0.5 积分。
3. **用户 Carol** 说"把我上周的 Git 提交生成一个幽默的周报"，万能入口自动编排「Git 日志提取 Skill」+「Prompt 润色 Skill」+「Markdown 排版 Skill」形成一个 DAG 执行流程。

## 3. 范围（Scope）

### 3.1 MVP 必含（In Scope）
- **万能入口 Skill** — 模型无关，同时适配 Claude Code、Cursor、Codex、OpenClaw 等 Agent 工具
- **意图 → DAG 拆解引擎** — 将用户模糊需求拆解为标准化的原子 Skill 步骤数组
- **Skill 市场基础功能** — 发布 Skill、检索 Skill、获取 Skill
- **本地运行沙箱** — 用户在自有算力上执行 Skill，不依赖中心化服务器
- **链上结算（Base）** — 智能合约只做两件事：①结算扣分/加分（流转凭证）②计数器 +1（状态证明）
- **本地 Append-only Log** — 记录所有高频运行数据，定期 Batch 打包上链
- **零服务器成本架构** — 全线跑在用户本地客户端

### 3.2 明确不做（Out of Scope）
- AI 自动评分系统（MVP 后迭代）
- 移动端客户端
- DAO 治理 / 链上投票
- 跨链支持（仅 Base）
- 传统 Web 前端页面（用户通过 AI 客户端交互）
- 实时 Debug 日志/中间状态上链
- 用户注册/登录系统（通过 AI 客户端原生身份）

## 4. 核心功能定义

### 4.1 万能入口 Skill（【核心】）
- **用户故事**：作为使用者，我只需用自然语言说出需求，无需了解底层 Skill 如何组合，以便零门槛使用社区能力。
- **行为**：接收自然语言 → LLM 拆解为标准化步骤数组（DAG）→ 在市场检索匹配 Skill → 在本地依次/并行执行 → 汇总结果输出。
- **边界 / 异常**：无匹配 Skill 时告知用户并建议创作；DAG 中某个 Skill 执行失败时回滚已执行的步骤。

### 4.2 Skill 市场（【核心】）
- **用户故事**：作为创作者，我把 Skill 发布到市场，每次被使用获得算力积分；作为使用者，我从市场获取 Skill 本地运行。
- **行为**：发布（上传 Skill 定义 + 元数据 + 定价）→ 链上确权 → 检索（按名称/标签/评分）→ 获取 → 本地缓存。
- **边界 / 异常**：Skill 版本管理 MVP 不做，后期再做；定价以积分为单位，结算在 Base 链上完成。

### 4.3 本地运行沙箱（【核心】）
- **用户故事**：使用者获取 Skill 后，在自己的机器上运行，不依赖任何中心化服务器。
- **行为**：Skill 下载到本地 → 在安全沙箱中执行 → 输出结果 → 执行计数写入 Append-only Log。
- **边界 / 异常**：根据 AI 客户端环境（Claude Code/Cursor）适配运行模式；恶意 Skill 的沙箱隔离在 MVP 阶段不做。

### 4.4 链上结算与计数器（【核心】）
- **用户故事**：创作者确信自己的使用量不会被篡改，使用者确信扣费透明。
- **行为**：本地 Append-only Log 定期 Batch → 提交到 Base 智能合约 → 合约校验并更新积分余额和计数器。
- **边界 / 异常**：Batch 提交失败时本地保留数据，下次重试；Gas 由系统代付或从积分中扣除。

### 4.5 Append-only Log 引擎（【核心】）
- **用户故事**：所有运行记录不可篡改地保留在本地，作为链上结算的事实依据。
- **行为**：每条执行记录以追加方式写入本地日志 → 日志结构化（时间戳、Skill ID、耗时、结果哈希）→ 定期 Merkle 化并 Batch 上链。
- **边界 / 异常**：日志只增不删；日志文件损坏时从最后一个已验证的状态恢复。

## 12. 假设与待澄清项（**复核结果**）
- Q1. **代币经济** ✅ MVP 先用积分（off-chain Points），验证分配算法后一键映射上链发币。
- Q2. **账户抽象** ✅ ERC-4337/EIP-7702 嵌入式钱包 + 会话密钥（Session Keys），AI 拥有受限自动签名权。
- Q3. **Skill 规范** ✅ 从第一天定义严格的 `skill.json` 标准（Pydantic 约束），对齐 LLM Tool Calling 格式（`name`/`description`/`input_schema`）。
- Q4. **DAG 并行** ✅ MVP 串行执行，复杂场景（抓取→总结→发送）本身就是线性的。
- Q5. **沙箱安全** ✅ 信任模式（仅种子开发者上架），市场开放时再补沙箱隔离。
