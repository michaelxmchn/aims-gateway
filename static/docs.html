AIMS Gateway Developer Guide

How to connect, use Skills, earn USDC, publish DRM-protected packages, and contribute to the mesh. No sign-up forms, no approvals — just your EVM wallet. Your first task is always free.

Quickstart: Run Your First Skill in 60 Seconds

You need two things: an EVM wallet and Python 3.10+.

★ First-Task-Free: Every wallet gets 1 free invocation per Skill — zero USDC required. After the trial, authenticated dev wallets are auto-seeded with 10.0 USDC (~200 invocations). No deposit needed.

Install the SDK

pip install eth-account requests

Create or import a wallet

# Generate a new wallet (for testing)
from eth_account import Account
wallet = Account.create()
print(f"Address: {wallet.address}")
print(f"Key: {wallet.key.hex()}")

# Or use an existing one
wallet = Account.from_key("0xYourPrivateKey...")

Sign and run a Skill

# scrape_products.py
import json, time, requests
from eth_account import Account
from eth_account.messages import encode_defunct

wallet = Account.from_key("0xYourPrivateKey...")

body = json.dumps({
    "skill_id": "amazon_scraper",
    "params": {"search_term": "RTX 5090", "max_results": 3},
    "user_id": wallet.address,
}, separators=(',', ':'))

signable = encode_defunct(primitive=body.encode())
signed = wallet.sign_message(signable)

headers = {
    "X-Wallet-Address": wallet.address,
    "X-Signature": signed.signature.hex(),
    "X-Timestamp": str(int(time.time())),
    "Content-Type": "application/json",
}

r = requests.post(
    "https://aims-gateway.fly.dev/api/run",
    data=body, headers=headers,
)
task_id = r.json()["task_id"]
print(f"Task: {task_id}")

# Poll until done
for _ in range(30):
    time.sleep(2)
    r = requests.get(f"https://aims-gateway.fly.dev/api/tasks/{task_id}/status")
    data = r.json()
    if data["status"] == "SUCCESS":
        print(data["result"])
        break
    elif data["status"] == "FAILED":
        print("Failed:", data)
        break

ⓘ No worker running? The task stays PENDING until a worker claims it. In production, workers are always online. For local testing, start a worker with python -m src.worker.worker.

⚙ Run a Node (Worker / Provider)

Two ways to earn on the network:

  • Worker — claim pending tasks, execute Skill logic, submit results. Earn 25% of the task fee (Q1 commission).
  • Provider — route encrypted traffic through your residential IP when idle. Get paid for bandwidth usage.
# Start a worker
AIMS_WALLET_KEY=0x... python -m src.worker.worker

# Or run as a provider (idle bandwidth)
from aims.provider import ResidentialRouteProvider
provider = ResidentialRouteProvider(wallet=your_wallet, region="us-west")
provider.start()

Three commerce modes. One unified protocol. Every Skill author chooses their pricing model; every consumer picks what fits.

MeteredPay per successful invocation. No commitments.Occasional use, testing, low-volume
SubscriptionMonthly pass with rate-limit guarantees.Regular power users, teams, production

Failed task? Your USDC never leaves escrow. The 402 safeguard rejects requests with insufficient balance before any funds move. If a worker fails to deliver valid results, the escrow refunds automatically.

AIMS-CLI Developer Toolchain Guide

The aims-cli is a hardened command-line toolkit for publishing DRM-protected Skills to the AIMS network. It handles the entire lifecycle: configuration, credential management, code obfuscation, encryption, signing, and gateway registration.

⚡ Prerequisites: Python 3.10+, pip install aims-cli (or run from source at bin/aims-cli). An EVM wallet with a private key.

Step 1: Project Configuration — aims-cli init

Interactive wizard that generates aims.config.json in your project root. The config is validated against the AIMSConfig Pydantic v2 schema — every field is type-checked, cross-validated, and circuit-broken against invalid combinations.

$ aims-cli init Enter skill_id [my_skill]: amazon_scraper_pro Enter entry_point [main.py]: logic.py Enter price_per_task_usdc [0.05]: 0.10 Select function_type: (1) worker_collab — Needs network compute (70/25/5 split) (2) direct_skill — No worker needed (95/0/5 split) [default] Select billing_mode: (1) pay_per_task — Metered usage [default] (2) subscription — Monthly recurring pass (3) buyout — Perpetual license Created aims.config.json — schema validated, circuit breakers active.

Key config fields:

FieldTypeDescription
skill_idstringUnique identifier for the Skill registry
entry_pointpathPython file exposing execute(payload) → dict
price_per_task_usdcfloatBase price per successful invocation
function_typeenumworker_collab or direct_skill
billing_modeenumpay_per_task, subscription, or buyout
enable_universal_free_trialboolAlways true — PLG enforced at protocol level

Circuit breakers (automatic validation):

  • worker_collab + buyout = BLOCKED — worker-collab mode depends on network compute arbitration, incompatible with perpetual licensing
  • subscription = rate_limit_per_day is MANDATORY
  • buyout = rate_limit_per_day is FORBIDDEN (perpetual = unlimited)

Step 2: Credential Management — aims-cli login

Securely stores your EIP-191 private key in an AES-256-GCM encrypted keystore (Web3 Secret Storage — keystore v3 standard). Your key is encrypted at rest with a password-derived key; the raw private key is never written to disk.

$ aims-cli login Enter your EVM private key (0x...): **************** Create a password for keystore encryption: ********** Confirm password: ********** ✓ Keystore created at ~/.aims/keystore.json (Web3 Secret Storage v3) ✓ Wallet address: 0x742d35Cc6634C0532925a3b844Bc9e7595f2bD18

Security properties:

  • Key derivation: scrypt (N=2^18, p=1) — GPU/ASIC resistant
  • Cipher: AES-128-CTR with random 16-byte IV
  • MAC: SHA-256(derived_key[16:32] || ciphertext) — tamper-proof
  • The keystore file is portable — copy it across machines safely
  • Password prompt uses getpass — no terminal echo

Step 3: DRM Build & Publish — aims-cli publish

This is the core of the AIMS toolchain. The publish command executes an 8-stage automated pipeline that transforms your raw Python source into a hardened, encrypted, signed, and registered DRM asset.

Pipeline Breakdown

Stage 3 — Obfuscation: The entry point is compiled into a native binary via PyArmor (primary) or Cython (fallback). The output wrapper.so replaces the original .py file — the gateway loads the shared object instead of raw source, preventing decompilation and unauthorized copying.

# What happens under the hood:
pyarmor obfuscate --output dist/wrapper.so logic.py
# Fallback if PyArmor not installed:
cythonize -3 -i logic.py → gcc -shared → dist/wrapper.so

Stage 4 — Encryption: All Python source files in the Skill directory are collected, archived, and encrypted with AES-256-GCM (random 12-byte nonce per operation). The resulting logic.enc is the canonical delivery artifact — only the gateway with the matching derived key can decrypt it at task time.

# Encryption parameters:
Algorithm:  AES-256-GCM
Key source: keccak(gateway_secret ++ task_id ++ user_address ++ random_nonce)
Nonce:      12 bytes random (unique per encryption)

Stage 5 — Signing: An EIP-191 signature is generated over the message AIMS-SKILL:{skill_id}:{key_hash}:{price_usdc}. This signature cryptographically proves authorship and is stored on-chain for royalty enforcement.

# Signed message format:
message = f"AIMS-SKILL:{skill_id}:{key_hash}:{price_usdc}"
signature = Account.sign_message(encode_defunct(message), private_key)
# Signer address recovered from signature — immutable proof of ownership

Stage 8 — Metadata Registration: The gateway records the Skill's routing metadata (skill_id, contributor address, function_type, billing_mode) via POST /api/skills/register-metadata. The encrypted source reference and contributor signature are stored for on-chain royalty verification. Duplicate registration returns HTTP 409.

ⓘ Idempotent publishing: If the upload or registration fails mid-pipeline, dist.zip is preserved on disk. Fix the issue and re-run — the pipeline skips completed stages where possible.

Authentication

AIMS uses EIP-191 personal_sign — the same signature format your wallet uses to sign transactions. No API keys, no bearer tokens, no shared secrets.

Every POST request to a protected endpoint needs three headers:

X-Wallet-Address: 0xYourEVMAddress
X-Signature:      <EIP-191 hex signature of the raw body>
X-Timestamp:      <UNIX epoch seconds>

The signature must be over the exact request body bytes (compact JSON, no extra whitespace):

# Python signing (client-side)
from eth_account.messages import encode_defunct

body = json.dumps(payload, separators=(',', ':'))  # compact!
signable = encode_defunct(primitive=body.encode())
signed = wallet.sign_message(signable)
signature_hex = signed.signature.hex()

Timestamps older than 300 seconds are rejected (replay protection).

Common Questions

Do I need to deposit real money?

Not to start. Every wallet gets 1 free invocation per Skill — no USDC required. After the trial, dev mode auto-seeds 10.0 USDC for testing. When mainnet launches, you can deposit real USDC or use subscription/buyout passes.

What are the three billing modes?

Metered — pay 0.05 USDC per successful task. Subscription — monthly pass with guaranteed rate limits, cancel anytime. Buyout — one-time perpetual license, unlimited usage, no recurring fees.

How does the revenue split work?

Q1 (worker_collab): 70% to the Skill contributor, 25% to the worker, 5% to the protocol treasury. Q2-Q5 (direct_skill): 95% to the contributor, 5% to the treasury. The split is enforced as immutable bytecode on the settlement contract..

What if a Skill fails?

Your USDC is never deducted. The escrow is automatically refunded. The worker receives a quality strike — repeated low AI Judge scores can lead to temporary suspension. For the free trial, LLM-as-a-Judge automatically arbitrates — if the result fails schema validation, the trial is not consumed.

Can I run this from a browser?

Yes — the AIMS Console is a full Web3 dashboard. Connect MetaMask, sign EIP-191 messages, and invoke Skills directly from the browser. The console supports all three roles: Consumer, Developer, and Worker.

What chains do you support?

Settlement runs on Base (EVM L2). Any EVM wallet works for auth — MetaMask, Rabby, Frame, or a raw key.

Is my data private?

Task payloads are encrypted in transit. Provider nodes see only encrypted bytes and routing metadata — never the content. Worker nodes receive only the task parameters, not your identity. For DRM-published Skills, source code is AES-256-GCM encrypted and PyArmor-obfuscated.

How do I protect my Skill source code?

Use the aims-cli publish pipeline. It automatically obfuscates your entry point to a native binary (wrapper.so via PyArmor/Cython), encrypts supporting source files with AES-256-GCM (logic.enc), and signs the package with your EIP-191 key for cryptographic authorship proof. The gateway only decrypts and loads your Skill at task execution time.
